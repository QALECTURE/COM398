01 · WHY HASHING?

Encryption hides data. What detects a change?

A confidential message may still be modified. Integrity asks whether the message has remained unchanged. Source authentication asks whether it came from the expected sender.

Confidentiality

Can an outsider read it?

Encryption helps hide contents.

Integrity

Has the content changed?

A trusted hash comparison can reveal changes.

Authentication

Who sent or authorised it?

MACs and signatures can provide origin evidence.

What is a hash family?

The lecture defines a keyed hash family using sets of messages X, digests Y, keys K, and a family of functions H. This is a mathematical way to describe a collection of related functions indexed by a key. Ordinary unkeyed SHA-256 is a single hash function; MACs later introduce secret-key use.

04 · HASH SECURITY PROPERTIES

Fast, deterministic, hard to reverse.

Speed

Efficiently compute the digest of a message.

Deterministic

The same input always produces the same output.

Avalanche effect

A tiny input change can drastically change the digest.

Preimage resistance

Given a digest, finding a message with that digest should be computationally infeasible.

Collision resistance

Finding two distinct messages with the same digest should be computationally infeasible.

Collisions exist

Infinitely many possible messages map into a finite digest space. Security is about making useful collisions hard to find.

05 · WHERE HASHES APPEAR

From downloaded files to password checks.

Software integrity

Compare a downloaded file’s digest with an authenticated reference. File-integrity monitoring tools such as Tripwire detect unexpected changes.

Timestamping

A hash can help commit to content without initially revealing it; a trusted timestamping system provides evidence of when a commitment existed.

Cryptocurrencies

Bitcoin uses SHA-256 in important protocol operations. A hash is not, by itself, anonymity.

Password verification

Systems verify a password against a stored password-derived value. Modern password storage needs a salted, slow password-hashing/KDF design such as Argon2id, not plain SHA-256.

Message integrity

Compare a received message’s digest against an authentic trusted value.

Digital signatures

Messages are commonly hashed as part of signing and verification.

MAC security

Even after seeing valid tags for messages of their choice, an attacker should not be able to produce a valid tag for a new message. This is the lecture’s chosen-message forgery idea.

Why not simply hash K || M?

For common Merkle–Damgård hashes, naive secret-prefix constructions can suffer length-extension attacks. HMAC uses a carefully designed inner and outer hashing construction instead.

Real HMAC-SHA-256 lab

Sender and receiver share a secret. Generate a tag, then modify the message or key and verify again.

HMAC is symmetric authentication: both parties know the shared secret. This demo uses the Web Crypto API where available, with a self-contained HMAC-SHA-256 fallback.

ipad repeats byte 0x36; opad repeats byte 0x5C; K′ is the key prepared to the hash input block size. The lecture also gives a high-level nested-hash intuition, but the formula above is the actual HMAC structure.

07 · DIGITAL SIGNATURES

Bob signs. Frank verifies.

The lecture follows Bob sending a signed document to Frank while an attacker tries to interfere. Signing uses Bob’s private key. Verification uses Bob’s public key.

Signing workflow

Document → hash/digest → signature algorithm with private key → signature sent alongside document.

Verification workflow

Received document + signature + authentic public key → verification algorithm → valid or invalid.

Interactive signature investigation

This is a workflow simulation to teach tamper detection; it is not a cryptographic digital-signature implementation.

Create a signature first.

Authentication

A valid signature, paired with a trusted public-key identity, helps establish the signer.

Integrity

Changing signed content makes verification fail.

Non-repudiation

Signatures can provide evidence against denial of signing, depending on identity assurance, key control and legal context.

01 // DATA ENCRYPTION STANDARD

DES and the Feistel Network

DES takes a 64-bit plaintext block, uses a 56-bit effective key, and produces a 64-bit ciphertext block. DES is a Feistel cipher. The major security concern highlighted in the lecture is its small 56-bit key.

A larger keyspace increases the work required for exhaustive search. DES's 56-bit key is the specific weakness highlighted by the lecture.

Step 1: split the block

A Feistel network divides a 2w-bit block into two halves, L₀ and R₀. The halves pass through multiple rounds. Each round uses a subkey Kᵢ derived from the overall key K.

The lecture specifies 16 DES rounds. The expansion stage grows the right half from 32 to 48 bits, it is XORed with the 48-bit round key, S-boxes reduce the result to 32 bits, and a permutation rearranges those bits.

03 // ADVANCED ENCRYPTION STANDARD

AES: transform the whole state

NIST sought a long-term replacement for 3DES. Rijndael was selected and AES was published as FIPS 197. AES is a symmetric block cipher using 128-bit data blocks and 128, 192 or 256-bit keys.

Exam distinction: AES-256 means a 256-bit key. It does not mean a 256-bit data block. The AES data block is 128 bits.

Unlike DES, AES is described in the lecture as an iterative rather than Feistel cipher. The 128-bit block becomes a 4 × 4 table of bytes called the state.

04 // RANDOM NUMBERS

Randomness is security material

The lecture uses randomness for public-key keys, symmetric stream key material, temporary/session keys, digital envelopes and handshaking values used against replay.

Uniform distribution

Values should occur with approximately the same frequency.

Independence

No value in the sequence should be inferred from other values.

Unpredictability

An opponent should not predict future values using earlier outputs.

The lecture states that encryption can be computationally secure when the cost of breaking the cipher exceeds the value of the protected information.

Time

It can also be computationally secure when breaking it takes longer than the useful lifetime of the information.

02 // HISTORICAL BACKGROUND

Learn weak ciphers to understand strong ones

Caesar Cipher

A substitution cipher. Shift every alphabetic character by the same key n. Encryption: Cᵢ = (Pᵢ + n) mod 26. Decryption: Pᵢ = (Cᵢ − n) mod 26.

LIVE ATTACK LAB

Encrypt, then attack Caesar

Waiting...
Kerckhoffs's Principle: good cryptographic security should not depend on hiding the algorithm. The algorithm may be public; the key must remain secret.
5–8 MINUTE CLASS ACTIVITY

Intercepted message

Attack this ciphertext using the brute-force tool:

GRR MGAR OY JOBOJKJ OT ZNXKK VGXZY

Find the readable plaintext. Then answer: why is Caesar fundamentally weak? What does this teach us about keyspace?

Shift 6 → ALL GAUL IS DIVIDED IN THREE PARTS. Caesar's keyspace is tiny, so an attacker can simply test every possible shift.

Vigenère Cipher

Vigenère uses a keyword and therefore a series of interwoven Caesar shifts. Repeat the key until it matches the plaintext length, then use each key letter to choose the shift.

LIVE VIGENÈRE
LECTURE EXAMPLE: HELLO + repeated key RPIRP → YTTCD.

Step 1

Find/estimate the repeating key length.

Step 2: Kasiski

Repeated ciphertext patterns can help reveal likely key-length relationships.

Step 3

Split positions into shift-cipher groups and apply frequency analysis.

Frequency analysis: natural-language letters and patterns are not equally likely. Classical ciphers can leak statistical structure.
HILL CIPHER

Groups + matrices

Hill cipher applies matrix mathematics to groups of letters. The lecture example maps ACT → POH. The important idea is that several symbols can be transformed together rather than independently.

ROT13

Fixed rotation by 13

ROT13 has no meaningful secret key. Apply it twice and the original text returns. Useful for simple obfuscation, not modern confidentiality.

04 // ONE-TIME PAD

Perfect secrecy — under demanding conditions

The lecture introduces the Vernam one-time pad as a first example of symmetric encryption. Message m and key k are bitstrings of equal length. Encrypt using c = m ⊕ k.

Click any plaintext/key bit

WHY OTP IS SPECIAL

Advantages

XOR is cheap; encryption and decryption use the same operation. Under the strict OTP conditions, ciphertext alone gives no preference to one possible plaintext over another.

WHY WE DON'T USE IT EVERYWHERE

Disadvantages

Key must be as long as plaintext. Truly random material is hard to generate/distribute at scale. OTP alone does not provide integrity. Reusing a pad is insecure.

VERY IMPORTANT: A true OTP needs a key that is genuinely random, secret, at least as long as the message and never reused. "One-time" really means one time.
ATTACK DEMO: KEY REUSE

What goes wrong when the same pad is reused?

If C₁=P₁⊕K and C₂=P₂⊕K, then XORing the ciphertexts cancels K:

C₁ ⊕ C₂ = P₁ ⊕ P₂

The attacker still has work to do, but the reused key has leaked a relationship between the two plaintexts. This destroys the OTP security guarantee.

05 // OPERATIONAL MODES

Stream cipher vs block cipher

STREAM CIPHER

Process a stream

The lecture describes plaintext being encrypted bit by bit. A keystream is generated from secret state/seed and combined with plaintext, commonly using XOR.

BLOCK CIPHER

A whole block is transformed under a key. A bit's output depends on other bits in its block.

06 // BLOCK CIPHER MODES

One block cipher, different ways to use it

Messages are usually larger than one block. A mode defines how successive blocks are handled. Your lecture covers ECB, CBC, CFB, OFB and CTR.

PATTERN-LEAK ATTACK THINKING

Why is ECB dangerous for structured/repeating data?

ECB encrypts each block independently with the same key. Identical plaintext blocks under the same key produce identical ciphertext blocks, so repetition can leak structure.

07 // THINK LIKE AN ATTACKER

Breaking the system is not always breaking the maths

Brute Force

Try possible keys until meaningful plaintext is found. Larger keyspaces make exhaustive search dramatically harder.

Cryptanalysis

Exploit structure, statistical properties, known plaintext/ciphertext relationships or weaknesses rather than blindly trying every key.

KEYSPACE VISUALISER

Attack 1: Tiny keyspace

Caesar: simply try every shift.

Attack 2: Statistical leakage

Frequency analysis can exploit patterns in classical substitution ciphers.

Attack 3: Key reuse

Reusing a one-time pad destroys its theoretical security guarantee.

Real security lesson: attackers often target implementation, configuration, endpoints, random-number generation, key storage or protocol misuse instead of mathematically defeating a strong cipher.
08 // INDUSTRY BRIDGE — AFTER CORE LECTURE

What this becomes in modern security

These are enrichment points after the prescribed lecture content. They connect today's ideas to current cryptographic engineering.

AEAD

Encryption + authentication

Modern systems commonly want confidentiality and integrity/authenticity together. AES-GCM is a widely encountered authenticated-encryption construction.

NONCE / IV

Not necessarily secret

Modes/constructions can require an IV or nonce. These values often need uniqueness or unpredictability according to the scheme; misuse can seriously damage security.

OPENSSL

Legacy algorithms

Current OpenSSL 3.x places older algorithms in its legacy provider. A DES lab can therefore behave differently from older tutorials.

2025 UPDATE

Lightweight Cryptography

NIST finalised SP 800-232 in August 2025, standardising Ascon-based primitives for constrained devices such as IoT and embedded systems.

QUANTUM CONTEXT

PQC is not an AES replacement

NIST's first PQC FIPS (203/204/205) standardise public-key key-establishment/signature mechanisms. Symmetric encryption such as AES solves a different problem.
